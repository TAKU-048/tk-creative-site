# tk-creative.org ブログ：週1本の記事を作って自動公開する手順

2026-11-11 ユーザー指示：
「小さなお店の経営者向けに、ホームページやGoogleマップ集客の悩みをテーマにした記事を週1本作成し、tk-creative.orgのブログに掲載する仕組みを追加してください。記事の最後には月額ホームページ制作サービスのページへのリンクを入れてください。記事は私の確認なしで自動公開し、公開前に日本語の誤りがないかチェックしてください。」

- 公開先：https://tk-creative.org/blog/（一覧）、https://tk-creative.org/blog/<slug>.html（記事）
- 公開のしかた：このリポジトリの main に入れると Cloudflare Workers Builds が自動で公開する。山浦さんの確認は取らない（ユーザー指示）。
- 実行：定期タスク「tk-creative.org ブログ 週1本の記事公開」が毎週1回この手順を行う。

## 0. 今週の分がもう出ていないか
- 公開は週1本（月曜〜日曜で1本）。`content/blog/` に、今週（日本時間）の日付の記事がすでにあれば、新しい記事は作らずに終える（報告に「今週の記事は公開済み」と書く）。

## 1. テーマを選ぶ
- `content/blog/topics.md` の「未使用」から1つ選ぶ。使ったら「使用済み」に日付と slug をつけて移す。
- 未使用が3つ以下になったら、同じ方向（小さなお店の経営者の、ホームページ・Googleマップ集客の悩み）で5つ足す。既存の記事と同じ内容にしない。

## 2. 原稿を書く（`content/blog/YYYY-MM-DD-<slug>.md`）
先頭に設定を書く：
```
---
title: 記事のタイトル（32文字前後）
description: 一覧と検索結果に出る説明（80〜120文字）
date: 2026-11-11（公開する日、日本時間）
slug: 半角英小文字・数字・ハイフン（例 google-map-basics）
category: Googleマップ集客 または ホームページ または お店の集客
---
```
本文の書き方：`## 見出し`（3つ以上）、`### 小見出し`、`- 箇条書き`、`1. 番号つき`、空行で段落、`**強調**`、`[文字](URL)`、`> 注記`。

書くときの決まり：
- 読み手は小さなお店の経営者。専門用語は使わないか、使うときは言い換える。です・ます調。本文2,000〜3,500文字。
- 悩み → 原因 → 今日からできること（具体的な手順）の順。
- **数字・制度・Googleの仕様など事実を書くときは、その回に Web 検索で公式の情報（Google のヘルプ、官公庁など）を確かめ、本文にリンクを入れる。** 確かめられないことは書かない。架空の事例・お客様の声・統計を作らない。
- 他社やツールを悪く言わない。「必ず上位に」「売上が◯倍」など結果を約束しない。
- TK-creative. のサービスは押しつけない。**最後の段落**に、月額ホームページ制作サービスのページへのリンクを必ず入れる：`[月額ホームページ制作サービス](../web-subscription.html)`（ページの最後の案内枠は build が自動で付けるが、本文の最後のリンクも必要）。
- サービスの内容・料金を書くときは web-subscription.html の記載どおりにする（初期制作費0円・月額9,600円（税別）など）。

## 3. 日本語のチェック（公開前に必ず）
1. `node tools/blog/check.mjs content/blog/<file>.md` を実行。エラーが0件になるまで直す。
2. AI が本文を最初から最後まで読み、次を確認して直す：誤字脱字・変換ミス、助詞の誤り、主語と述語のねじれ、同じ言葉の繰り返し、敬語の誤り、表記ゆれ（「ホームページ／HP」「Googleマップ／グーグルマップ」など）、一文が長すぎないか（目安60文字）、事実の根拠リンクがあるか。
3. 直したら 1. をもう一度実行する。

## 4. ページを作って公開する
1. `node tools/blog/build.mjs`（blog/ の記事ページと一覧を作り直す）
2. `node tools/blog/check.mjs`（全記事。0件であること）
3. `git add content/blog site/tk-creative.org/blog && git commit` → `git push origin main`
4. Workers Builds の結果が成功になることを確かめる（`gh api repos/TAKU-048/tk-creative-site/commits/<sha>/check-runs`）。
5. 失敗した場合は直して出し直す。直せない場合は公開を取りやめ、原稿を `draft: true` にして残し、理由を報告する。

## 5. 記録
- `content/blog/topics.md` の使用済みに追記。
- 実行の結果（公開した記事のタイトルとURL、チェックで直した点）を報告する。
